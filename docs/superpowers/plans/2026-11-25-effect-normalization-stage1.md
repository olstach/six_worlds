# Effect Normalization — Stage 1: Vocabulary, Resolver, Validator — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the shared effect language (approved lists, a resolver for the core ops, value paths with fortify/drain/damage holds, and a validator in GDScript and Python) **without converting any content**, so stage 2 (statuses) has something to migrate onto.

**Architecture:** A new folder `scripts/effects/` holds four static-function classes:
- `EffectVocab`: the approved lists, plus `validate()`.
- `EffectContext`: who and what an effect resolves against.
- `ValuePaths`: reads and holds values on units and characters.
- `EffectResolver`: one function per op.

The resolver delegates to the modules that already work (`StatusOps`, `Repositioning`, `ResourceOps`, `SaveSystem`, `Resurrection`, `Zone`, and the `CombatManager` functions that call them). Nothing reads the new code from content yet. It is exercised only by a new verifier scene and a Python unit test.

**Tech Stack:** Godot 4.7 / GDScript, Python 3 (`unittest`), `tools/verify_all.sh`.

**Spec:** `docs/superpowers/specs/2026-11-25-effect-normalization-design.md` (§4.1, §4.2, §5, §6 stage 1). Stages 2–6 get their own plans, written when the stage before is merged.

## Global Constraints

- Work on a branch: `git checkout -b normalization-stage1`. The working tree has uncommitted edits by Olaf (`CONTENT.md`, `project.godot`, `companions.json`, `shops.json`, `content_base.json`). **Never stage those.** Every commit lists its files explicitly; never use `git add -A` or `git add .`.
- **No content JSON changes in this stage.** No file under `resources/data/` is edited. The game must play exactly as before. The only additive engine changes are: getters read effect holds (empty in play), `damaged_values` is read (empty in play), and holds are cleared at combat end.
- A new `class_name` requires committing `.godot/global_script_class_cache.cfg` in the same commit (CLAUDE.md).
- GDScript quirks (CLAUDE.md): `not x in y`, never `x not in y`; typed arrays are initialized (`Array[Dictionary] = []`).
- Comment code for a beginner-intermediate reader (Olaf). Every public function gets a `##` doc comment saying what it is for.
- Vocabulary lists contain **only what is built**. A name goes into an `EffectVocab` list in the same task that makes the resolver handle it. Unknown names fail validation loudly: `push_error` in GDScript, `err()` in `validate_data.py`. Nothing returns a silent default.
- Run `tools/verify_all.sh` at the end of every task; it must exit 0. The new verifier is picked up automatically by the `tools/verify_*.tscn` glob.
- The magnitude shapes, mode semantics and value-path namespaces are exactly the ones in spec §4.1–4.2. Where this plan narrows them for stage 1, it says so.
- Rest tiers in `overworld.gd`: 1 = Quick Rest, 2 = Camp, 3 = Full Rest. `cleared_by` `rest: "quick"|"camp"|"full"` clears at `effective_tier >=` 1, 2 and 3 respectively.

## Review Focus

1. **A combat hold leaking into the character after the fight.** A `fortify`/`drain` applied in combat must be gone from `character_data` (attributes, `skill_bonuses`, derived) once `end_combat` runs. Test in Task 5.
2. **Double counting.** Re-applying the same hold source twice must replace it, not stack. Releasing it must restore the exact pre-hold value, including for `multiply` and `set`. Test in Task 3.
3. **`damage` mode on an enemy.** There is no persistent character to write to. It must last for the fight only and must not touch `EnemySystem` data. Test in Task 6.
4. **`kill` on a boss.** It must be refused by default (spec §7), with a log line, and the effect log must say `refused`. Test in Task 8.
5. **A save/load round trip.** `damaged_values` must survive it, and the derived stats after loading must equal those before saving. Test in Task 6.

### Task 7: EffectResolver core: context, shared fields, `damage` / `heal` / `modify`

**Files:**
- Create: `scripts/effects/effect_context.gd` (`class_name EffectContext`, `extends RefCounted`). Fields:
  - `caster: Node`, `target: Node`, `area_units: Array`
  - `container_kind: String` (`"spell"`, `"test"` …), `container_id: String`
  - `power: int`: the spellpower bonus as `_calculate_spell_bonus` computes it today
  - `level: int`, `school: String`
  - `save_result: Dictionary`: empty until a save is rolled; shared by all effects of one container (spec §4.3)
  - `hold_source: String`: when set, `fortify`/`drain`/`set`/`multiply` register holds under it; when empty, those modes are refused with an error
- Create: `scripts/effects/effect_resolver.gd` (`class_name EffectResolver`)
- Modify: `.godot/global_script_class_cache.cfg`

**Interfaces:**
- Produces:
  - `static func resolve(effects: Array, ctx: EffectContext) -> Array[Dictionary]` returns a log, one entry per effect per recipient: `{"op", "to": unit_name, "applied": bool, "reason": String, "amount": float}`.
  - `static func magnitude(spec: Variant, ctx: EffectContext, recipient: Node) -> float`.
  - `static func recipients(selector: String, ctx: EffectContext) -> Array`.
- Shared-field rules, applied in this order, per effect and per recipient:
